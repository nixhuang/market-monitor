  · afaf5fb 定时 run 美东 10-16 20:17 → 同样 today=1 / prior=99 / stale=99

  → 结论：源端当日日线的就绪时间**每天不固定**（10/15 要等到 22:30 后，10/19 在 19:12 前就好了）。
    之前我说「20:15 两个源都没更新」太绝对，用户对：不是那个点必然没数据。
- 但让用户每天看到「99 只失败」的是两个设计缺陷：
  ① 失败轮照样 git commit index.html + status.json 并发布 → 把上一次的好页面覆盖成「当日行情未取得 99 只」
     （51039ae:index.html 里就是这行字，上一版 e2ed81a 还是「完成于 10-16 23:14」的好数据）。
  ② ensure-morning.yml（美东 20:45）的 ensure_schedule_run() 只判断 status.json 有没有
     target_trade_date + mode=closed + total，**不看质量** → 失败轮留下的 status 被当成「结果已存在」→ 不补跑。
     于是一整天停在坏数据上，直到有人手动重跑。
- 待改（用户未授权，未动手）：A 质量门槛（stale+missing 占比过高就不提交/不发布，页面标「沿用上次数据」）；
  B 补跑判定加质量条件；C 可选：主定时点后移或失败后等待重试（build timeout 15 分钟不够，需延长/拆 job）。
