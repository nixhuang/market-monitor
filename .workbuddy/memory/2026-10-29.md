## 冬令时（美东 11/1 起 EST）：**自动切换，无需改代码**（只读核查结论）
- 调度唯一入口是 Cloudflare Worker `market-monitor-trigger.js`：cron 用 **UTC**
  `15,45 0,1 * * TUE-SAT`（UTC 不受 DST 影响），再用 `Intl.DateTimeFormat(timeZone:America/New_York)`
  把投递时刻换算成美东，闸门 `planned.hour==='20' && minute∈{15,45} && weekday Mon~Fri`。
  夏令时美东 20:15 = UTC 00:15，冬令时 = UTC 01:15 —— 两条都在 cron 里，错季节的被闸门丢掉。
  **前提：Cloudflare 面板上的 cron 必须真的含 0 和 1 两个小时**（只配 0 会漏掉整个冬令时）。
- GitHub 侧 daily.yml **没有 schedule**（已注释），只 workflow_dispatch + Worker 派发；
  补跑窗口用 `TZ=America/New_York date +%-H` 判 20–24 点，跟随 DST。
- monitor.py / market_sessions.py 全部用 `zoneinfo.ZoneInfo('America/New_York')`（US_TZ），
  美东 20:00 锚点、收盘窗口判断自动跟随。
- 页面显示的是北京时间（UTC+8，中国无夏令时）**不变**；但抓取对应的北京时刻会后移 1 小时：
  夏令时 08:15/08:45 → 冬令时 09:15/09:45。

  「本地保存失败，尚未持久化；请导出备份，刷新可能丢失改动」），仓位标题行同步胶囊就显示黄字
  **本地未持久化**，底部 NOTICE 提示导出备份。含义＝本页写不进 localStorage，改动只在内存里。
- 常见触发：file:// / iOS Chrome 打开本地文件、隐私模式、站点存储被禁、配额满。线上是 https，不会出现。
- 实测（headless Chrome 桌面）：同一份 DEMO 用 file:// 打开 → 胶囊渲染为 **「隔离预览 · 不上传」**
  （isolated=true 分支优先于 nocloud）；http://127.0.0.1 打开 → **「只读标签页」**（headless 下
  navigator.locks 拿不到 writer）。**headless 结果不能代表真机 iOS**；用户在手机上看到「本地未持久化」
  说明 iOS Chrome 对本地文件禁用了 localStorage。
- 排查套路：dump-dom 后**先剥掉 <script> 块**再正则取 `<span class="warn|ok|dim"...>文字</span>`，
  否则会把 JS 里的字面量当成渲染结果（第一次就是这么误判的）。

## 金额宽度护栏：大额自动降精度（2026-10-29 晚）
